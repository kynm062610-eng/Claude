# テクニカル手法 候補リサーチ(2026-09-24)

YouTube・note・個人ブログで人気のテクニカル手法を集め、**1分足OHLCだけで機械的に検証できる形**に落とした候補リスト。
まだ1つも検証していない。検証前に research_ledger.md の既存9候補と重複していないか確認すること。

> 注: このクラウド環境からは note.com・個人ブログの本文を開けない(ネットワーク制限)ため、ルールは検索結果の要約から再構成している。
> 各手法の「元ネタ」と完全一致ではなく、**検証用に一意に定義し直したもの**として扱う。

---

## 0. 先に押さえておく前提

1. **学術的な先行結果は厳しい。** Neely & Weller (2003) は、為替の日中テクニカルルールは
   現実的な取引コストを入れ、流動性の高い時間帯に限定すると利益機会の証拠がないと報告。
   テクニカルルールの利益は知られるほど減衰する、という結果も複数ある。
2. **人気手法の多くは裁量を含む。** 「ダウ理論」「水平線」「ネックライン」「環境認識」は人によって定義が違う。
   機械化するときの定義の選び方そのものが自由度になり、試行数(DSRのN)を膨らませる。
   → **定義は検証前に1つに固定し、ここに書いたとおりに実装する。** 結果を見てから定義を変えたら、それは新しい試行。
3. **1分足スキャルはコストで死にやすい。** 1分足BB(期間9・2σ)のような手法は1トレードの値幅が小さく、
   スプレッド(USDJPYで0.2〜0.3pips程度)が期待値の大半を食う。判定基準どおり「1分足の終値で約定」+スプレッド控除で評価する。
4. **重複の疑い:** 既存の `orb_research.py`(オープニングレンジ・ブレイクアウト)は、
   ネットで人気の「ロンドンブレイクアウト」「東京ボックスブレイク」とほぼ同じ構造のはず。台帳で確認し、重複なら候補から外す。
5. **試行数:** 台帳の累積は9。以下の候補を1つ検証するたびにN=10, 11, … と増やす。
   同じ手法のパラメータ違いも1試行ずつ数える。

## 1. 候補一覧(機械化した定義)

時刻はすべてUTCで定義(データのタイムゾーンは fx_data.py 側で要確認)。
上位足は1分足からリサンプリングし、**確定した足だけ**を使う(先読み防止)。

### T1. パーフェクトオーダー + 押し目(ぶせな式・グランビルの法則の機械化)
- **出典の系統:** 「移動平均線がパーフェクトオーダー」+「ネックラインが引ける」でエントリーする順張り(ぶせな氏ブログ)、グランビルの押し目買い。
- **定義:**
  - 環境: 1時間足 SMA20 > SMA75 > SMA200 かつ3本とも前の足より上向き → 買いのみ(売りは逆)。
  - トリガー: 5分足の安値がSMA20(5分足)に触れた後、5分足終値がSMA20の上で確定。
  - 約定: トリガー確定の次の1分足の終値。
  - 損切り: 直近12本(5分足=1時間分)の最安値の1pip下。利確: 損切り幅×1.5。時間切れ: 24時間。
- **想定トレード数:** 年数百回/ペア → 必要トレード数は満たしやすい。

### T2. ダウ理論のマルチタイムフレーム押し目(note系で最多の型)
- **出典の系統:** 「上位足で環境認識 → 下位足の転換で入る(上位足の押し目買い)」(ずん氏ほか多数)。
- **定義:**
  - スイング高値・安値: 左右3本より高い(安い)足をフラクタルとして確定(右3本の確定後に初めて使える)。
  - 環境: 1時間足で直近2つのスイング高値・スイング安値がともに切り上がり → 上昇トレンド。
  - トリガー: 5分足が直近の5分足スイング安値を割らずに、直近の5分足スイング高値を終値で上抜け(下位足の下降→上昇転換)。
  - 損切り: 直近の5分足スイング安値の1pip下。利確: 1時間足の直近スイング高値。ただし損切り幅の1倍未満なら見送り。
- **注意:** フラクタル幅(3本)と時間足の組み合わせが最大の自由度。**3本・1時間/5分で固定**し、変えない。

### T3. 1分足ボリンジャーバンド逆張り(アジア時間限定)
- **出典の系統:** 1分足スキャル向けの「期間9〜10・2σ」設定、「逆張りは出来高が来ないアジア時間で有効」という通説。
- **定義:**
  - 時間帯: 00:00–05:00 UTC(東京時間の前半。仲値の時間帯を含むので、仲値要因と混ざる点に注意)。
  - エントリー: 1分足終値が BB(20, 2σ) の外側 → 次の足の終値で逆張り。
  - 決済: 終値がミドルラインに到達、または損切り=エントリーからBB幅(±2σの距離)ぶん逆行、または30分経過。
- **見どころ:** 勝率は高く出やすいが、損益比とスプレッドで負けるのが典型。**コスト控除後の期待値だけで判定する。**

### T4. RCI 3本(9/26/52)の順張り押し目
- **出典の系統:** 「RCI3本」手法(短期・中期・長期のRCIの並びで判断。-80%以下でのゴールデンクロスは強いシグナル)。
- **定義(15分足):**
  - 環境: RCI52 > 0 かつ RCI26 > 0 → 買いのみ。
  - トリガー: RCI9 が -80 を下から上に抜けた足の確定。
  - 決済: RCI9 が +80 を上から下に抜けた時点、または損切り=ATR(14)×1.5。

### T5. ボラティリティ・ブレイクアウト(ラリー・ウィリアムズ)
- **出典の系統:** 『ラリー・ウィリアムズの短期売買法』の「ボラティリティ・ブレイクアウト」。暗号資産ボットでも定番。
- **定義:**
  - 日の区切り: NY 17:00(FXの日足の標準的な区切り)。
  - 買い: 当日始値 + 0.5 × 前日レンジ(高値−安値)を1分足終値で上抜け。売りは対称。1日各方向1回まで。
  - 決済: 当日の区切り(翌NY17:00の直前の1分足終値)で手仕舞い。損切り: 前日レンジ×0.5。
- **想定トレード数:** 約2,800営業日 × 発生率 → 1,000回超/ペア。
- **注意:** ORB(orb_research.py)と構造が近い。台帳と照合。

### T6. 日中モメンタム(学術寄り)
- **出典の系統:** Elaut, Frömmel & Lampaert (2018, *Journal of Financial Markets*)。RUB/USDで「最初の30分のリターンが最後の30分のリターンを正に予測する」ことを確認。
  原因は情報トレーダーではなく、**流動性供給者がポジションを持ち越したくないこと**(=構造的な理由がある)。
- **FXへの置き換え(定義):**
  - 1日の区切り: NY 17:00。
  - シグナル: 最初の区間(東京時間 00:00–00:30 UTC)の方向。代替案は1つだけ事前登録: ロンドン 07:00–07:30 UTC。
  - 取引: 最終区間(NY 20:30–21:00 UTC 相当 = 日の区切り前の30分)にシグナル方向で建て、区切り直前の1分足終値で決済。
- **注意:** 元論文は取引所で取引されるRUB/USDで、24時間OTCのUSDJPY/EURUSDでそのまま成立する保証はない。
  1取引あたりの値幅が小さいのでスプレッドの影響が大きい。

### T7(優先度低). チャートパターン(ダブルトップ/三尊のネックライン抜け)
- YouTubeで非常に人気だが、ジグザグの閾値・肩の高さの許容差・ネックラインの定義など自由度が多すぎる。
  **機械化した時点で「その定義の手法」になり、元の裁量手法の検証にはならない。** 後回しを推奨。

### T8(優先度低). 移動平均線ゴールデンクロス単体
- ネット上の検証でも勝率4割程度・大きくばらつくという報告が多い。単体の検証価値は低い。T1にフィルターとして吸収済み。

## 2. 推奨する検証順

| 順 | 候補 | 理由 |
|---|---|---|
| 1 | **T2 ダウ理論MTF押し目** | note・YouTubeで最多の型。機械化できれば「ネットの主流手法に優位性があるか」に答えが出る |
| 2 | **T1 パーフェクトオーダー押し目** | 定義の自由度が小さく、トレード数も十分 |
| 3 | **T6 日中モメンタム** | テクニカルの形だが、流動性供給者の持ち越し回避という構造的な理由付きで、元の方針とも両立する |
| 保留 | T5 | ORBと重複の可能性。台帳確認後に判断 |
| 保留 | T3, T4 | コスト負けの事前確率が高い。T1/T2 の結果を見てから |

3つ検証すると N=12 になり、DSRの期待最大シャープ(帰無仮説下)が上がる分、有意のハードルも上がる。
**上から順に1つずつ検証して台帳に記録**し、候補を増やしすぎない。

## 3. 各候補の検証チェックリスト(台帳の判定基準)
- [ ] 定義をこのファイルのとおりに固定してから実装(実装後に定義を変えたら別試行)
- [ ] 約定 = シグナル確定の次の1分足の終値。スプレッド控除あり
- [ ] 上位足はすべて確定足のみ(先読みテストを test_*.py に入れる)
- [ ] IS/OOS の両方で成立(区切りは既存エンジンと同じ年で)
- [ ] 必要トレード数を満たす
- [ ] DSR ≥ 0.95(N = 台帳の累積試行数 + 1)
- [ ] 結果にかかわらず research_ledger.md に記録
