# 安全・プライバシー設計

> 本書は製品設計のための整理であり、法的助言ではない。リリース前に弁護士のレビューを受けること。
> 各国法およびストアガイドラインは改訂されるため、実装時点の最新条文を必ず確認する。

---

## 1. 「同意」「閲覧」「開示」を分ける

保護者に関わる機能を 1 つの設定にまとめてはいけない。法が要求しているのは **同意** であって、保護者が子どもの書いた内容を常時読めること（＝監視）ではない。

| 層 | ON/OFF | 根拠 |
|---|---|---|
| **① 保護者の同意**（登録時） | 切れない（必須） | 個人情報保護法：委員会 Q&A 上、おおむね 12〜15 歳以下は法定代理人の同意が必要とされる。米国配信時は COPPA の検証可能な保護者同意（13 歳未満）。EU は GDPR（13〜16 歳、加盟国による） |
| **② 保護者の日常的な閲覧** | **OFF にできる（初期値 OFF）** | いずれの法域も「保護者が内容を常時閲覧できること」は要求していない |
| **③ 保護者の開示・削除請求** | 権利自体は切れない（申請ベースで可） | COPPA は保護者に子どもの個人情報を確認・削除させる権利を定める。GDPR / 個人情報保護法にも開示・削除の請求権がある |

つまり **「見ない設定」は作ってよい。ただし ① と ③ は無効化できない。**

### 実装上の帰結

- 登録フローで保護者の同意を必ず取り、同意日時・同意した文言のバージョンを記録する。
- 保護者コンソールに「開示請求」導線を常設する。閲覧モードが OFF でも押せる。
- 開示請求が行われたら **子どもにも通知する**（後述の透明性原則）。

## 2. 見まもりモード（3 段階）

保護者コンソールで切り替える。**初期値は OFF。**

| モード | 保護者に見えるもの |
|---|---|
| `off`（初期値） | 何も見えない。グループ数・参加人数などのメタ情報のみ |
| `notify_only` | 「今日ノートを書いた」という事実と日時だけ。本文・画像は見えない |
| `full` | 子どもが所属するノートの全ページを閲覧できる |

### 設定に関わらず必ず作動する「安全フロア」

見まもりモードの値に関係なく、以下は常に有効。ここは製品として譲らない。

1. **NG ワード検知時** — 投稿前に本人へやさしい警告。検知種別によっては保護者へ通知。
2. **通報が発生したとき** — 通報者・被通報者双方の保護者へ通知。
3. **個人情報らしき文字列の検知** — 電話番号・住所・学校名らしきパターンを投稿前に検出し、本人に確認を促す（保護者通知はしない。まず本人の学習機会にする）。
4. **運営によるモデレーション** — 通報された投稿は運営が閲覧できる。プライバシーポリシーに明記する。

## 3. 透明性の原則（製品の芯）

**子どもの画面に、現在の見まもりモードを常時表示する。**

```
ノート上部のバッジ:
  off          →  「おうちの人：見ていません 🙈」
  notify_only  →  「おうちの人：書いたことだけ伝わります 🔔」
  full         →  「おうちの人：見ています 👀」
```

- **保護者がモードを変更したら、子どもに通知する。** 親がこっそり `full` に切り替えて黙っている、という状態を作らない。
- 開示請求が実行されたときも子どもに通知する。

理由は 2 つある。

1. **倫理**: 本人に知らせない監視は、たとえ保護者によるものでも子どもの信頼を壊す。9〜12 歳は「親に見られたくない」が芽生える時期であり、ここを雑に扱うとアプリを使わなくなる。
2. **製品**: 「見られている前提」が分かっていれば、子どもは納得して使える。隠すより開示するほうが結果的に安全な投稿が増える。

## 4. 収集しない情報

| 項目 | 方針 |
|---|---|
| 本名 | 収集しない。ニックネームのみ |
| 顔写真・任意の画像 | 収集しない。アバターはアプリ内プリセットから選択 |
| カメラ | 権限自体を要求しない |
| 位置情報 | 権限自体を要求しない |
| 連絡先 | 権限自体を要求しない |
| 子どものメールアドレス | 収集しない。認証は保護者アカウントに紐づく |
| 生年月日 | 収集しない。学年のみ（同意要否の判定に使う） |
| 広告 ID / サードパーティトラッキング | 使わない。行動ターゲティング広告を入れない |

## 5. ストア審査への対応

法律より先に詰まるのは、実際にはここ。小学生向け ＋ UGC（子ども同士の投稿）は審査が厳しい。

### 必須実装（Apple / Google 共通で求められる 4 点）

1. **不適切表現のフィルタリング** — `src/lib/moderation` の NG ワード判定
2. **通報導線** — 全ページに通報ボタン。通報は運営キューに入る
3. **ブロック** — 特定ユーザーの投稿を見えなくする。グループ制のため「退出」も併用
4. **問い合わせ先の公開** — アプリ内・ストア掲載ページ・プライバシーポリシーに記載

加えて、通報への対応体制（目安として 24 時間以内の削除）を運用として持つ。**「保護者が見ているから大丈夫」は審査を通らない。** モデレーションは運営の義務として実装する。

### そのほか

- Apple のキッズカテゴリに出す場合、外部リンク・課金・外部ブラウザ遷移にはペアレンタルゲートが必要。MVP では外部リンクを一切持たないことで回避する。
- Google Play の Families ポリシーに沿った対象年齢申告と、ソーシャル機能の申告を行う。
- 年齢確認は「保護者アカウント経由の登録」で担保する。

## 6. データ保持と削除

- 退会時、子どものプロフィール・ページ・リアクションを削除する。
- ただし **通報に紐づく投稿は、通報処理が完了するまで保持**する（安全対応のため）。この例外はプライバシーポリシーに明記する。
- ノートは複数人の共同著作物であるため、1 人の退会で他の子のページまで消さない。退会者のページは「たいかいした子」として匿名化し、本文は削除する。
- バックアップからの完全削除は 30 日以内を目安とする。
